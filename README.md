# Quotern

Quotern is a Rust workspace. The current `quotern-core` crate reads selected, consented OpenCode SQLite/WAL and JSON sources and stores source-reported token observations locally. These observations do not establish verified consumption or provider quota.

The `quotern-ffi` crate builds the core as a static library behind a versioned C ABI (`Sources/CQuotern/include/quotern.h`, eight exports, JSON envelopes defined by `Contracts/bridge-v1`), and the Swift package `Quotern` wraps it in a headless `EngineClient` (library, client and tests only; there is no native application executable yet). The Rust source acquisition, history and bridge tests use temporary fixtures and do not require provider credentials or a live OpenCode account.

## Source behavior

SQLite sources are opened through a read-only VFS that never creates, writes, truncates, syncs, deletes, or changes permissions of source files. The pinned Unix parent's `open`, `fstat`, `stat`, `lstat`, `readlink` and `access` entries are interposed: every by-name open is forced read-only and non-blocking, and the descriptor the kernel returns (not the path that was requested) must be a regular file with the inode that was probed before the open, so a path swapped for the instant of the open (a FIFO, another database, a `-shm` replaced after its check) is refused rather than read or waited on. Each of those physical calls is charged against the pass's 40,000-call metadata ceiling immediately before it runs. A live WAL database is read only while its writer runs in another process. If a writer shares this process, or a mapping cannot be shown to be read-only, the source is reported unavailable rather than read. SQLite's Unix VFS shares one shared-memory node per database inode inside a process, so a reader whose database is already open elsewhere in the process reuses that node without opening or statting the `-shm` sidecar; a pathname check cannot vouch for it. Each shared-memory mapping is therefore bound to a file itself: it must have been requested read-only, made from the descriptor whose `fstat` immediately preceded the `mmap`, and that descriptor must name the inode the sidecar path names when the map is validated, otherwise the read fails closed. The kernel's present protection of an existing mapping is not re-queried by the product. A call refused before it reaches the kernel (an exhausted metadata allowance, a rejected descriptor) returns `-1` with `errno` set to `EBADF`, because SQLite's `robust_open` retries an `open` that fails with `EINTR` without bound. No network, provider account, or credential is used.

The application history store is created and opened relative to a directory handle bound to the validated data root, and the by-name SQLite open of `history.sqlite` is checked at the kernel level against that handle's inode (sidecars must be regular and unaliased), so a path swapped for the instant of the open is refused before any pragma or migration. An existing store is admitted only after effect-free checks: the header version, a non-empty write-ahead log's committed frames (served over the main file through the read-only VFS, so schema that exists only in the log is compared exactly), and an exact comparison of the amended v1 schema objects. A hot rollback journal, a foreign, newer or earlier-shaped unshipped store is refused with every byte, sidecar and mode untouched. History rows are never rescanned at admission.

Each source-reported record keeps its total's provenance (`reported` or `derived`, with the pinned `codexbar-3239175f-disjoint` convention when derived, including a part group that mixes explicit and derived part totals) and how it was acquired: `sqlite_read_transaction` for one message group read in one SQLite read transaction, `file_by_file_best_effort` for JSON files validated before and after reading. A source projection reports `mixed` when both are represented; it never claims one source-wide simultaneous snapshot. JSON records are parsed with `serde_json`'s default recursion limit, so nesting up to 127 levels (counting the top-level object) is supported; records are at most 262,144 bytes.

Part directories, SQLite part rows and database sweeps larger than one pass resume across passes from bounded state. A JSON message's held part scan keeps the pass catching up (never idle, consistent or terminal) until its final revalidation, which is itself resumable, has finished; a SQLite part group that spans passes resumes only while a snapshot witness (main-file size and change counter plus write-ahead-log size, salts and checkpoint sequence) shows no commit since it began, and otherwise restarts, so cached parts are never mixed with newer source data under a single-transaction label. The terminal unchanged-proof walks every completed database in pages of 256. Wire decoders (`ObservationPage`, `Snapshot`, `SourceSnapshot`) bound sequences and strings while reading, require every nullable field to be present (an explicit `null` is allowed), and validate each raw record and projection relationally. An unavailable pass publishes nothing; idle and busy sources back off from 5 s doubling to 5 min on an injected clock, persisted across reopen.

A held JSON part scan lives only in memory; no OS directory-iterator position is ever saved. A restart therefore reads the message's part directory again from its beginning, and the pass stays catching up until that scan finishes. The directory that lists the scanned message stays pending in the persisted frontier even after its own listing reached the end, and completed directories and published history are kept. While the scan is held that directory still counts against the 4,096-directory queue ceiling, so the queue never grows past the ceiling. A child directory that does not fit is not dropped: the pass reports `limit_exceeded` and stays catching up, and the listing that yielded it goes to the back of the queue and is read again from its beginning once the directories ahead of it have drained and made room, so every child of a finite stable tree is eventually listed before a generation can end consistent. Once a generation's directory frontier has drained, the reserved current lane stops starting new refreshes of known JSON messages (databases, failed files and any held scan still resume), so a stable tree whose refresh costs more than that lane's half of the budget still ends consistent. A first reopen pass over a message known from an earlier generation is driven by the known-path lane instead. Staging a partly read group never moves published numbers, revisions or the last-good time; only a finished, revalidated group does. Verified limits: one group of more than 40,000 raw part entries drains after one restart, and a known group with 20,001 extra part entries drains after one restart without moving last-good until it publishes.

## Proof provenance and limits

Several kinds of evidence are kept apart; none of them is a proof that no source effect can occur on any machine.

**Candidate accounting.** The pass counters (`stat_calls`, `entries`, `directory_opens`, `bytes_read`) and the in-crate `test-faults` ticks and `vfs_metrics` are the candidate's own accounting. The `RecordingFs` comparison in `source_boundary` checks the counters against those ticks, so it cannot see work that is neither ticked nor charged.

**Requested flags (M1).** `VfsProbe` in `tests/support/vfs_probe.rs` records the flags SQLite requested from an `xOpen`. Requested flags are not effective access.

**Independent native physical observer** (`support::physical_native`, used by `source_boundary` and by two `opencode_wal` fixtures, macOS arm64 only). It exports `stat`, `lstat`, `fstat`, `fstatat`, `readlink`, `access`, `realpath`, `opendir`, `fdopendir`, `closedir`, `readdir`, `readdir_r`, `read`, `pread`, `readv`, `preadv` and `close` from the test executable. The production code, `std` and the bundled SQLite call them, so it sits beneath the pass counters and the production syscall hooks, and it reads none of the production counters, ticks or hook statistics. It counts attempts that cross the native API with a source-root path (matched under the given and the canonical spelling, for example `/tmp` and `/private/tmp`) or through a source descriptor (bound by the descriptor's own path at the call, or by having been seen opened or `fstat`ed there). On every such descriptor call it also reads the kernel access mode with `F_GETFL`, so a source descriptor open for writing is counted whichever library opened it, and it counts how many checked calls went through a `-wal` and a `-shm` descriptor. It does not wrap `open` (a variadic function), and raw kernel syscalls, libsystem-internal path walks, `mmap`-consumed bytes and every other target are outside it.

The ceilings it applies are the literal per-pass limits: 40,000 metadata calls, 64 directory opens, 8 held directory streams and 20,000 yielded entries, common to JSON and SQLite acquisition, and no writable source descriptor. The 67,108,864 raw-read-byte ceiling bounds the materialized JSON quantity only. SQLite page reads are neither charged nor bounded by it: the SQLite quantity is the payload bytes the pass materializes, and a SQLite pass is only required to have read at least that many raw bytes. Foreign-thread source work, table overflow (128 streams, 1,024 descriptors), failed closes and unreadable access modes are coverage faults and are never clamped.

The observer replaces process-wide symbols, so each test that arms it re-executes the test binary as a single-test child (`--test-threads=1`, killed after 600 s) and arms it after its fixtures exist. Its state is fixed-size and allocated before arming, no native call is made while its lock is held, every hook returns the native result with `errno` as the native call (for `readdir`, the caller) left it, and dropping the armed observer disarms it, also while unwinding. Its controls run real native work: charged-without-native and native-without-charge work each make the same detector reject, the exact ceilings are reached with real calls, writable descriptors are rejected through every hooked descriptor call, and descriptor-table overflow, failed `close`, a stream read error (a descriptor closed beneath a valid stream), vector reads, foreign threads and unwinding are exercised against the real native functions. The engine's SQLite passes (JSON and WAL-only fixtures, and a fixture whose raw page reads exceed 64 MiB while the materialized payload stays inside its budget) are reconciled against it, as are metadata allowances taken from zero to the full cost of one SQLite read, including the allowance that ends between the two `fstat`s the production hook performs.

**Independent kernel observation (M2)** (`support::vfs_probe::kernel`, macOS arm64 only). It asks the kernel rather than the VFS: descriptor access modes from `F_GETFL` over a live-descriptor sweep (which sees the WAL descriptor the VFS opens itself, including while the engine holds it during a pass), mapping protections from `mach_vm_region`, and a chain link over the "unix" VFS's `open`, `mmap` and `fstat` entries that records the parent's successful opens and maps and its failing `fstat`s. The link is armed in the test process (it replaces entries of a process-global table), serialized by the VFS test guard, and not run in a child. Its buffers are allocated when it starts and never grow inside a callback; an event beyond a buffer's ceiling is dropped and recorded as a sticky overflow that fails `finish` and every oracle. Callbacks return the parent's value and `errno` unchanged, hold no lock across the parent's call, and mark events made by other threads. `finish` restores the exact saved entries and verifies them; `Drop` restores them on a best-effort basis and discards a failure.

Requested and granted mapping protection are separate checks with separate controls (a read-only request later raised by the kernel is red only on the live granted check; a writable request is red on both). A cached shared-memory node is exercised in both states: reuse with an unchanged sidecar is accepted, reuse after the sidecar path was replaced by another inode with identical bytes is refused. Controls with a really writable open, a really writable mapping, a retained direct writable WAL descriptor and a reused in-process writable mapping (made before and after the probe) turn the same predicates red. Its ceiling is that the sweep sees descriptors open at the instant it runs and the link sees the parent's `open`, `mmap` and `fstat` entries; neither sees a transient descriptor that a direct libc call opened and closed in between, a mapping made before the probe started, or the product's own write-free paths other than through those entries.

Lifecycle and receipt rules of those proofs. A connection that detaches from the shared-memory node (`xShmUnmap`) loses its validation, so its next map is checked against the sidecar path again even when another reader kept the cached node alive; `a_connection_that_detached_is_validated_again_when_it_attaches_to_the_cached_node` drives a real map, unmap, replacement of the sidecar by another inode with identical bytes and remap on one connection. A delegated `open` that fails after the pre-open probe gives back the metadata charge it reserved for the descriptor's validation `fstat` and leaves the kernel's `errno` untouched, so the meter equals the independent physical count on the failed read and on its retry. Each probe callback is admitted into the observation generation that is armed, and the generation waits (a bounded 10 s, never holding the lock over a native call) for callbacks that were already running when it is finished: their events are kept and attributed, a callback that cannot finish in time fails the restoration loudly, and its late event never enters a probe started afterwards. A participating native caller (the `fetch_*` and `call_*` functions and the `SyscallProbe` methods) registers with the armed generation before it reads the entry from the table and until its call returns, so the wait also covers a caller paused between the fetch and the call: its event is kept, attributed to its thread and recorded into the generation it fetched under, with the kernel's exact result and `errno`; if it has not reached the callback within the bound, `finish` fails loudly and the late call is forwarded unobserved and never recorded into a probe armed afterwards. The registration belongs to each fetched handle alone: one thread may hold several, dropping or invoking one releases only its own, and the callback finds only the handle being invoked (`overlapping_fetched_handles_on_one_thread_own_their_registrations_and_receipts` and `a_stale_fetched_handle_never_touches_a_later_probes_registrations` cover the drop and invoke orders, an old handle beside a new one, and an old handle beside a helper fetched while no probe was armed). A registered fetch whose table read finds the entry already restored is refused and fails the observation, and at most 64 registrations are pending at once, one more being refused and failing it (`a_fetch_registered_before_the_table_read_never_finishes_clean_after_restoration`, `acquisitions_are_bounded_and_an_unwinding_handle_releases_its_registration`, which also unwinds with a handle held: the setup is outside the caught region, the panic is required by a private marker, and the two destruction orders are real; the handle goes first with the probe alive outside the catch, so the registration is back while the generation is still armed and `finish` is clean with its exact receipt, and the probe goes first, so its restoration fails within the bound with the handle still held and `Drop` keeps that failure in a state of its own). SQLite's `xGetSystemCall` and `xSetSystemCall` read and write a plain pointer with no synchronization, so every call the helper makes to either (the saves, installations and read-backs of `start`, the restoration, the participating fetch and `SyscallProbe::table`) holds one gate, never across a native call, a quiescence wait or a paused caller, and is recorded in a bounded order witness. `the_table_gate_serializes_participating_reads_installation_and_restoration` holds the gate from the test and shows, by contention counters and the witness and with no timing, that a fetch of each entry, `table()`, a restoration, and an installation (at its saves and, paused, at its installation) wait for it and have accessed nothing, and that a real fetch and a real restoration contending for it end in one of their two serial orders (observed, or refused with the observation failed); the participant is never run against a conflicting raw access, so without the gate the test fails before any. The gate orders participants only: SQLite's own unix VFS and code reading the table itself take no gate, so a mutation is defined only while no such reader runs on another thread, a controlled premise of the suites (probes are armed under the VFS test guard and the engine's own opens run on the arming thread); no claim is made about arbitrary concurrent SQLite use. `a_nested_invocation_restores_the_stale_outer_one_when_it_returns` and `a_nested_invocation_keeps_the_outer_ownership_while_the_probe_restores` run a participating `open` from the test's open hook inside another (the production hook runs inside the outer handle's call) and check exact receipts, pending and in-flight counts, and that a plain call made once the inner one has returned belongs to the outer invocation again (unobserved for a stale outer, recorded and drained for the probe being restored). `a_caller_paused_between_fetching_an_entry_and_calling_it_is_drained_or_fails_the_proof` drives open, map and `fstat` through the drained, timed-out and rearmed cases, by channels and exact outcomes, not elapsed time. The live-descriptor sweep names a descriptor to the kernel with a raw `fstat` into the SDK's `struct stat` (never a `File`, `OwnedFd` or `BorrowedFd`, which another thread may close at any instant) and skips a descriptor only on `EBADF` while it is still closed. That coverage is of participation only. SQLite's own unix VFS, and any code that reads the table or `xGetSystemCall` itself, fetches without registering: restoration does not wait for it, and a callback fetched that way before a restoration is forwarded unobserved when it runs with no probe armed, or attributed to whichever probe is armed then (`an_entry_fetched_without_registering_is_outside_the_probes_coverage` pins this). No completeness is claimed for every acquisition in the process. Every live-descriptor sweep taken inside the engine's callback is retained, failed ones included, and checked after the pass; a buffer overflow, observation fault or failed restoration fails the consumer of the receipts, with real cap and cap + 1 controls on failing `fstat` receipts and, on a fresh probe in which no other buffer can overflow, on failed `open` receipts (exact `-1` and `ENOENT`, every oracle and `finish`, owner and foreign threads). The sweep's failure is a real one: `a_failed_descriptor_sweep_among_successes_fails_the_wal_access_proof` runs the real sweep through the engine's shared-memory open after a successful one, against a descriptor that is still open and that the kernel refuses to describe (the slave of a revoked pseudo-terminal), and `a_descriptor_closed_between_the_sweeps_checks_is_skipped_and_hides_no_open_failure` closes a descriptor between each pair of the sweep's checks, alone and ahead of such a failing one. Foreign open, map, failing-`fstat` and failed-`open` attribution each have a foreign-thread case and an owner-thread control. The consumer of a refused SQLite stage must be a budget stop (`CatchingUp`, no failure code, nothing committed), the zero allowance is a separate case that never reaches the open, and every other allowance must have run the stage, been measured, and consumed exactly its allowance, with a receipt showing whether the refusal came before the hook's first `fstat` or between its two.

**Store creation and bounded-inventory proofs** (`opencode_wal`, all platforms). `fresh_v1_native_interruption_retry_history_and_encoded_consumer` re-executes the test binary as child processes: store creation is interrupted once by the in-crate fault (before the version statement) and once by killing the child while its creation transaction holds the complete schema and `user_version` 1 uncommitted (the `test-faults`-only `migrations::set_creation_hook`, a one-shot thread-local callback that does not exist in the default build). A new process must then find the empty store, create it, ingest and exit, and a further new process must reopen it and expose the retained history before any pass; the schema is compared with a literal object list, never rebuilt from the production DDL. `revision_generation_tie_fault_reopen` drives one JSON group through a clean pass, a pruned part, an explicit zero and two competing acquisitions of the same path, with the revision commit and the conflict handling faulted before, after or not at all, and checks every step through the decoded history page, the decoded snapshot, the event row, the maintained group row and the maintained totals. `completed_database_beyond_the_legacy_window_is_revalidated_before_certification` edits, in place, a completed database outside the first 1,024 of the former terminal window among 1,089 independent databases and requires every consistent report to carry the edit. The 4,500-directory and 300-message regressions measure each pass physically (`RecordingFs`, thread-local physical operations), compare it with literal ceilings and with the reported counters, and record which directories reached their end. These are fixture-bound evidence for those cases, not a proof for every source tree.

**Original-proof discriminators** (`opencode_wal`). The two whole-engine bounded-inventory fixtures, `directories_beyond_the_queue_ceiling_are_fully_inventoried` and `stable_known_messages_beyond_the_current_lane_budget_reach_consistent_across_one_reopen`, run as the only test of a re-executed child (macOS arm64, killed after 900 s) that arms the native observer after the fixtures exist. For every pass it compares the native counts with the literal ceilings and with the charged counters (metadata calls, directory opens, yielded entries, JSON bytes, at most the bytes requested), rejects a writable source descriptor, a coverage fault or more than eight held streams, and requires that no stream or descriptor remains once the engines are dropped. The production accounting (`physical_operations`, `RecordingFs` metrics) is still asserted beside it, not instead of it. The current-lane refresh starts a new directory-EOF epoch before its generation, keeps it across its one reopen and certifies only a complete epoch; its terminal pass advances last-good to exactly its injected time, and the reconstruction pass commits no record and leaves last-good unchanged. That pass is designated by the restart-blocked directories read from the durable frontier before the engine is dropped, never by the report under test, and must be exactly the `Partial`/`limit_exceeded` reconstruction report. The fault tests read every cursor, frontier, file-metadata, staged-candidate (payload included), baseline, failure and inventory row and the generation counters straight after the faulted pass and a reopen, before any later pass: a before-commit fault leaves exactly the pre-pass rows, and an after-commit fault leaves the finalized generation (G2) or the discarded one (G3) with no acquisition-local row. Before the G3 fault the saved backlog cursor is non-NULL, fewer rows than one pass reads remain after it, and the open frontier (the root, and `storage` unless the native listing order left it to the known-file lane; both orders are run: the backlog database's name is chosen on the actual source root itself, from the positions of that entry and of `storage` in its real native listing, checked again right before the pass and printed per case, never predicted from another directory, and the test fails unless six cases of each order ran), file metadata, staged competitor (its stored payload compared with the fixture's exact numbers, not only its key and fingerprint) and baseline are the expected set, so the fault reaches the discard and not an earlier staging write. After a killed fresh-schema creation and before the retry process starts, an independent reader finds no schema and version 0; the encoded snapshot envelope (outcome, failure, source identity, last-good time, counters) is compared with literals, the actual report and the durable status row. The 1,089-database consumers compare the complete decoded and durable set of (source, session, message, record id, time, input value, revision) with the set written from the fixture index. These are source-level proofs of those cases only.

Fixtures are synthetic, hand-authored databases and trees; what a test exercises is the production code run on them, and a control shows that a detector turns red on one named, real effect. A passing run is evidence for those cases only.

## Build and test

Run these commands from the repository root:

```sh
cargo test -p quotern-core --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
```

The source and privacy proof suites can be run directly:

```sh
cargo test -p quotern-core --locked --test opencode_wal --test source_boundary --test sentinel_sinks
```

The independent native proofs can be run on their own (macOS arm64). The physical observer tests replace process-wide symbols, so each runs in a re-executed single-test child; the M2 tests arm a restorable link in the test process and serialize on the VFS test guard:

```sh
cargo test -p quotern-core --locked --test source_boundary -- physical_native --nocapture --test-threads=1
cargo test -p quotern-core --locked --test opencode_wal -- directories_beyond_the_queue_ceiling_are_fully_inventoried stable_known_messages_beyond_the_current_lane_budget --nocapture
cargo test -p quotern-core --locked --test opencode_wal -- m2_kernel_oracle reused_writable_shared_memory cached_readonly requested_and_granted kernel_probe_state refused_opens spike_m2_live spike_s1_live spike_s6 a_failed_descriptor_sweep a_descriptor_closed_between failed_open_receipts a_caller_paused_between an_entry_fetched_without overlapping_fetched_handles a_stale_fetched_handle a_fetch_registered_before acquisitions_are_bounded the_table_gate a_nested_invocation restoring_a_probe_waits a_callback_that_outlives a_connection_that_detached a_failed_delegated_open --nocapture --test-threads=1
```

The integration tests use synthetic fixtures, temporary SQLite databases, and child writer processes. They do not contact providers or use user databases.

## Bridge and Swift client

The reported daily snapshot is Rust-owned: `today_snapshot` takes `{tz, now_ms}`, the Rust core derives the local-day window and sums only the records inside it, and Swift never filters, re-windows or sums. A request whose instant is outside `0..=253402300799999`, whose zone is unknown, or whose local day has an endpoint outside that range (for example Asia/Kolkata or Europe/Riga at `now_ms` 0) is `invalid_request`, never clamped. One native owner holds each data directory (`flock` on the directory); a second owner gets `store_busy`. The client contract, error table and first-success example are in [Contracts/bridge-v1/README.md](Contracts/bridge-v1/README.md).

Build the Rust archive with the explicit deployment target before any Swift step; the Swift package links only `target/aarch64-apple-darwin/release/libquotern_ffi.a`:

```sh
MACOSX_DEPLOYMENT_TARGET=14.0 cargo build -p quotern-ffi --release --locked
swift build
swift test
swift test --sanitize=thread --filter CancelTokenTests
```

The bridge proofs on the Rust side:

```sh
cargo test -p quotern-core --locked --test reported_today
cargo test -p quotern-ffi --locked --test contract_v1 --test ffi_ownership --test sentinel_sinks --test repo_policy
```

`repo_policy` also holds `forbidden_runtime_in_release_artifacts`, which stays ignored until a native executable is relinked and is then run explicitly with `-- --ignored --exact forbidden_runtime_in_release_artifacts`. The release static library never enables the `test-faults` feature; the test seams reach `quotern-ffi` only through its dev-dependency. The Swift live tests start `/usr/bin/sqlite3` as a fixture writer child.
